# 本番リサーチ・特許リストCSV仕様

## 1. 位置づけ

本番環境では、各リサーチフォルダに調査対象特許の一覧CSVが格納される。この文書は、2026-07-16時点で確認されたファイル名と列形式を記録する。

現行アプリはこのCSVを直接読み込む。CSVがない場合はリサーチ直下の `patents.json` を読み込む。移行前データに限り、旧 `subresearches/*/patents.json` も読込互換として扱う。

## 2. ファイル名

```text
patent_list_{yyyymmddHHMMSS}.csv
```

例：

```text
patent_list_20260716153045.csv
```

タイムスタンプ部分は14桁で、`yyyy`、`mm`、`dd`、`HH`、`MM`、`SS` の順とする。同一リサーチフォルダに複数存在する場合は、ファイル名のタイムスタンプが最新の1ファイルだけを対象とする。取込実装では採用ファイルと除外した旧ファイルを監査情報へ記録する。

UIアップロードでも元のファイル名を保持する。現在有効なCSVより古いファイルは履歴として保存するが対象集合を変更しない。同名・同内容は登録済みとして扱い、同名で内容が異なるファイルは上書きせず拒否する。新しい最新版へ切り替わった場合はリサーチを再分析必要状態にし、夜間一括分析の全件再分析完了後に解除する。

## 2.1 CSV物理形式

本番ファイルについて、次の形式を確認済み。

| 項目 | 確認済み仕様 |
|---|---|
| 文字コード | Shift_JIS互換のCP932。BOMなし |
| UTF-8 | 使用されない。UTF-8前提で読み込んではならない |
| 改行コード | CRLFのみ。LF単独、CR単独は確認されていない |
| 列区切り | カンマ |
| 複数番号・複数日付セル | 引用符で囲まれている |
| 空欄 | 引用符付き空文字 `""` |
| ヘッダー | 前後空白や位置ずれなし |
| PDF拡張子 | 小文字 `.pdf` |

取込処理は明示的に `encoding="cp932"`、`newline=""` を指定してCSVパーサーへ渡す。UTF-8への自動フォールバックで文字化けした値を取り込まない。

## 3. ヘッダーと値形式

列順は確認されたCSVの順序を保持する。

| 列名 | 値形式 | 例 | 備考 |
|---|---|---|---|
| `No` | 半角数字 | `1` | 同一リスト内で一意。リサーチをまたぐ一意性はない |
| `AIスコア` | 小数第1位までの半角数値 | `85.3` | 数値の尺度・範囲は未確認 |
| `出願番号` | `特願yyyy-x...` または `特願平x-x...` | `特願2024-1234`、`特願平5-1234` | 後半番号はゼロ埋めされていない |
| `出願日` | `yyyy.mm.dd` | `2024.01.15` | 年月日はピリオド区切り |
| `公開・公表番号` | 国内番号、WO番号、またはカンマ区切りの複数番号 | `特開平5-1234`、`WO2022/0442209`、`特表2024-530685,WO2022/0442209` | 国内番号後半はゼロ埋めなし。WO番号はゼロ埋めあり |
| `公開・公表日` | `yyyy.mm.dd`、または番号と同順のカンマ区切り複数日付 | `2023.06.13,2021.11.12` | 年月日はピリオド区切り |
| `登録番号` | `特許第XXXXXXX号` | `特許第7654321号` | 未登録時の空欄表現は未確認 |
| `登録日` | `yyyy.mm.dd` | `2026.03.10` | 未登録時の空欄表現は未確認 |
| `出願人・権利者名` | テキスト | `株式会社サンプル` | 原文を保持する |
| `発明の名称` | テキスト | `加工状態監視装置` | 原文を保持する |
| `ステイタス` | テキスト | `通常審査中` | 確認済み語彙は「3.3 ステイタス」を参照。原文を保持する |

正確なヘッダー行：

```csv
No,AIスコア,出願番号,出願日,公開・公表番号,公開・公表日,登録番号,登録日,出願人・権利者名,発明の名称,ステイタス
```

### 3.1 番号・日付の複数記載

`公開・公表番号` には、国内公開・公表番号とWO番号が同一セルに併記される場合がある。

```text
公開・公表番号: 特表2024-530685,WO2022/0442209
公開・公表日:   2023.06.13,2021.11.12
```

番号と日付は記載順で対応するものとして扱う。

| 順番 | 公開・公表番号 | 公開・公表日 |
|---|---|---|
| 1 | `特表2024-530685` | `2023.06.13` |
| 2 | `WO2022/0442209` | `2021.11.12` |

取込時には単一文字列のまま意味解析せず、順序を維持した配列へ変換する。番号数と日付数が一致しない場合は、自動的に対応を推測せず警告対象とする。

CSVの列区切り自体もカンマであるため、複数番号・複数日付を含むセルは通常、CSV上で引用符に囲まれている必要がある。

```csv
"特表2024-530685,WO2022/0442209","2023.06.13,2021.11.12"
```

取込処理ではPythonの `csv` モジュール等のCSVパーサーを使用し、行を単純に `split(',')` してはならない。実ファイルで引用符が付いていない場合は不正形として検出し、専用の補正規則と監査記録が必要になる。

### 3.2 WO番号とPDFファイル名の差

CSVではWO番号の年と連番の区切りが `/` だが、PDFファイル名では `-` になっている場合がある。

```text
CSV記載:    WO2022/0442209
PDFファイル: WO2022-0442209.pdf
```

照合キー生成時だけ `/` と `-` を同一視する。CSV原文、表示用番号、PDFファイル名はそれぞれ変更せず保存する。WO番号の連番はゼロ埋めを保持し、数値化によって先頭ゼロを失わないよう文字列として処理する。

国内番号では、CSVとPDFファイル名で後半番号のゼロ埋め桁数が異なる場合がある。原文を保存したうえで、照合キーでは番号種別・年・後半番号を分解し、後半番号の先頭ゼロを除いた数値同等性でも比較する。ただし、表示値やPDFファイル名そのものは書き換えない。

### 3.3 ステイタス

`ステイタス` 列で確認された値は次のとおり。表記、全角／半角、括弧内の補足を含め、CSV原文をそのまま保存する。

1. `通常審査中`
2. `登録（権利有）`
3. `年金不納による抹消`
4. `拒絶査定（審判：請求不成立）`
5. `未審査請求によるみなし取下`
6. `審査請求無し`
7. `審判中`
8. `拒絶査定（1年経過）`
9. `拒絶`
10. `登録（権利有：審判完）`
11. `存続期間満了による抹消`
12. `登録査定（最新審査中間C参照）`
13. `取下`
14. `拒絶査定（１年未満・最新審査中間C参照）`
15. `放棄`
16. `放棄による抹消`
17. `新規出願(経過情報なし)`
18. `出願却下処分（登録）`
19. `拒絶査定（審判：審判請求取下）`
20. `拒絶査定（審判：決定却下）`
21. `拒絶査定（審判：請求手続き却下（旧請求無効））`
22. `拒絶査定（審判：請求成立）`
23. `早期審査中`
24. `登録査定（特許／登録）`
25. `登録（経過情報なし）`
26. `付与後異議による抹消`
27. `国内優先権に基づくみなし取下`

取込処理では、上記を既知値として照合しつつ、未知の値もエラーで破棄せず原文のまま保存する。`拒絶`、`拒絶査定`、審判結果、登録査定、権利存続中、抹消などは意味が異なるため、文字列の部分一致だけで同一状態へ統合しない。UI用の大分類が必要な場合は、原文とは別の派生フィールドとして変換規則と版を保存する。

## 4. 取込時の基本方針

- ヘッダー名で列を特定し、列位置だけに依存しない。
- `No` はCSVファイル／リサーチ内の行識別にのみ使用し、リサーチ横断IDには使用しない。
- 特許番号の後半を勝手にゼロ埋めせず、CSV原文を保存する。
- 国内番号の後半は勝手にゼロ埋めせず、WO番号の既存ゼロ埋めは失わない。
- 比較・PDF照合用には、全角／半角、空白、ハイフン種別、WO番号の `/` と `-` を正規化した別キーを生成する。
- 平成年は西暦へ変換した検索用情報も持つが、`特願平x-...`、`特開平x-...` の原文を保持する。
- 複数番号と複数日付は順序を維持した配列として保持し、要素数の不一致を警告する。
- 日付原文は保持し、内部処理ではISO形式 `yyyy-mm-dd` へ変換する。
- `AIスコア` は小数第1位まで保持できる数値として読み込むが、尺度が確定するまで脅威マップの `similarity` や `concept_level` へ直接流用しない。
- `AIスコア` は別システムの検索プロンプトとの一致度であり、高いほど検索条件との一致が強い。広めに収集するための参考値として原文保存し、本システムの分析・マップ配置には原則使用しない。
- 年次フィルタには `出願日` の年を使用する。
- `ステイタス` は原文を保存する。リサーチごとの「権利化」「審査中」判定テキストへ完全一致した場合だけ各区分へ分類し、どちらにも一致しない値は「公開」へ分類する。
- PDFとの対応候補が複数ある場合は、`登録番号`、国内の`公開・公表番号`（特開・特表・平成表記を含む）、WO番号、必要に応じて`出願番号`の順で優先する。
- 同じ文献の公開公報と登録公報が存在する場合は、登録に近いPDFを優先する。国内公報とWO公報では国内公報を優先する。
- 採用したPDFだけでなく、検出した候補、優先規則、採用理由を監査記録へ残す。
- PDFが見つからない行は取込対象から消さず、分析だけをスキップしてUIへ表示する。状態を `skipped`、理由を `pdf_not_found` として保持する。
- 出願人名や発明名称などの特殊文字は一律に削除しない。CSV原文を保存し、NUL等の処理不能な制御文字だけを除去または置換して監査記録へ残す。

## 5. 想定する変換先

CSV原文を失わないよう、将来の取込処理では書誌情報とアプリ用情報を分ける。

```json
{
  "pdf": "WO2022-0442209.pdf",
  "publication_number": "特表2024-530685",
  "publication_numbers": [
    {"number": "特表2024-530685", "date": "2023-06-13", "kind": "domestic"},
    {"number": "WO2022/0442209", "date": "2021-11-12", "kind": "wo"}
  ],
  "application_number": "特願平5-1234",
  "registration_number": "特許第7654321号",
  "application_date": "1993-01-15",
  "publication_date": "2023-06-13",
  "registration_date": "2026-03-10",
  "applicant": "株式会社サンプル",
  "title": "加工状態監視装置",
  "source_status": "審査中",
  "source_ai_score": 85.3
}
```

現行実装は同等のフィールドをメモリ上の文献レコードへ変換し、UIとパイプラインの共通入力にする。`patents.json` を生成して原本CSVを置き換えることはしない。

## 6. 現行実装の監査情報

- 採用した `selected_csv`
- 除外した `excluded_older_csvs`
- 行数と取込警告（番号と日付の個数不一致、No重複、AIスコア不正、制御文字除去）
- 各行のPDF候補、採用候補、照合キー、優先規則

これらはダッシュボードAPIとパイプライン実行マニフェストに保持する。パイプライン開始後は、実行中にフォルダ内のCSVが変更されても対象集合を変更しない。
